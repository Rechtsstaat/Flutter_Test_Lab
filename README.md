# Flutter_Test_Lab

한 번 입력한 표준 매물 데이터를 **당근·다방·직방**의 매물 등록 폼에 함께 반영하는 것을 목표로 하는 Flutter 실험 프로젝트입니다.

## 프로젝트 목표

플랫폼마다 같은 매물 정보를 반복 입력하는 불편을 줄이기 위해, 공통 데이터 모델과 하나의 통합 입력 화면을 만들고 각 플랫폼의 공식 연동 방식 또는 사용자 승인을 거친 입력 흐름으로 연결하는 것이 최종 목표입니다.

목표 흐름은 다음과 같습니다.

1. 사용자가 앱에서 표준 매물 정보를 한 번 입력합니다.
2. 앱이 당근·다방·직방에 필요한 필드로 데이터를 변환합니다.
3. 사용자가 내용을 확인하고 승인합니다.
4. 각 플랫폼의 지원 범위에 따라 공식 API 연동 또는 폼 입력 보조를 수행합니다.

## 현재 상태: 직방·다방 폼 주입 프로토타입

현재 구현은 완성된 3사 통합 등록 앱이 아닙니다. 통합 폼의 값을 앱 내부 WebView에 표시한 **직방 또는 다방 재현(미러) 폼**에 주입하고, 입력 결과와 플랫폼이 받지 못한 항목의 사유를 확인하는 단계의 프로토타입입니다.

현재 확인할 수 있는 범위:

- 통합 매물 입력 폼과 테스트 데이터 자동 채우기
- 조건부 필수값 및 일부 입력 규칙 검증
- 필수값 완료 시 `직방에 보내기`와 `다방에 보내기` 버튼 활성화
- 직방·다방 재현 폼으로 플랫폼별 값 전달
- WebView DOM 재확인을 통한 입력 성공 여부 표시
- 직방·다방 양쪽의 주소 검색을 WebView 안의 전체 화면 카카오 우편번호 화면으로 표시
- 주소 선택 후 이어지는 화면 처리 — 다방은 동·호 입력과 건축물대장 창, 직방은 소재지 공개 확인 창
- 다방 관리비 상세 창 입력·종료
- 플랫폼에 대응하는 필드가 없거나 브라우저 보안상 자동화할 수 없는 항목의 사유 표시

### 주소 검색

두 미러 모두 주소를 카카오 우편번호 서비스로 받습니다. 카카오의 `Postcode.open()` 은 `window.open()` 으로 별도 창을 띄우는데, WKWebView 에는 팝업 창이 없어 그 요청이 같은 웹 뷰에 실리면서 미러 폼이 빈 화면으로 덮였습니다. 지금은 `daum.Postcode` 를 감싸 두고 `open()` 요청을 **같은 인스턴스의 `embed()`** 로 바꿔, 페이지 안에 세운 전체 화면 겹에 그립니다. 미러가 넘긴 `oncomplete` 를 그대로 살려 두므로 주소를 고른 뒤의 흐름(다방의 동·호 활성화와 건축물대장 창, 직방의 주소 칸 채움과 소재지 공개 확인 창)이 원래대로 이어집니다. 기기의 뒤로 가기는 이 겹을 먼저 닫습니다.

주소와 좌표를 임의로 확정하지는 않습니다. 통합 폼에 입력한 주소는 카카오 검색창에 검색어로 미리 들어가고, 사용자가 결과를 한 번 고르면 나머지는 자동으로 이어집니다. 다방의 건축물대장 자동 조회 창은 이미 입력한 면적·용도·승인일이 공공데이터 값으로 덮어써지지 않도록 「직접 입력」으로 닫고 그 사실을 제한 사유에 남깁니다.

현재 포함되지 않은 범위:

- 당근 폼 연동
- 실제 직방 사이트 로그인 또는 실제 매물 등록
- 플랫폼 공식 API 연동, 사진 자동 업로드, CAPTCHA 처리
- 다방 건축물대장 조회 결과의 자동 선택·적용 및 비목별 관리비 금액 변환
- 운영 환경의 장애 복구 및 등록 결과 동기화

상세한 공통 필드와 플랫폼별 대응 방향은 [부동산3사 통합 기능명세서](./부동산3사_통합_기능명세서.md)를 참고하세요.

## 실행 방법

Flutter SDK와 iOS 실행 시 Xcode/CocoaPods를 준비한 뒤, 저장소 루트에서 다음 명령을 실행합니다.

```bash
flutter pub get
flutter devices
flutter run
```

특정 기기를 지정하려면 다음과 같이 실행합니다.

```bash
flutter run -d '<기기 ID>'
```

iOS 실기기에서 처음 실행할 때는 `ios/Runner.xcworkspace`를 Xcode로 열고 Runner 타깃의 Team과 고유한 Bundle Identifier를 설정해야 할 수 있습니다.

## 검사 및 테스트

저장소 루트에서 다음 명령을 실행합니다.

```bash
flutter analyze
flutter test
```

## 실제 서비스 적용 전 확인 사항

이 프로젝트는 연구용 프로토타입이며 현재 실제 서비스에 매물을 등록하지 않습니다. 실제 연동을 구현하기 전에는 각 플랫폼이 제공하는 공식 API나 제휴 수단을 우선 확인하고, 이용약관과 자동화 정책을 준수해야 합니다. 또한 매물·계정·연락처·사진 등 개인정보의 수집 및 보관 범위, 전송 전 사용자 확인과 명시적 승인, 인증정보 보호, 오류 발생 시 복구와 중복 등록 방지 절차를 함께 설계해야 합니다.
